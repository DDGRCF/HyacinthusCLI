# 结果和确认

## 输出

需要机器读取时显式传 `--format json`，不依赖 profile 的默认格式。JSON stdout 是 `{ok, data, error, meta}` envelope；成功的 `--output` 文件是裸 data。按已知来源读取，形态不符就报告，不能用缺字段回退猜格式。`--jq` 只缩减 stdout，支持简单路径和 `[]`；复杂处理用工作区小脚本，不假定已安装 jq。

`ok: true` 只代表请求成功，导入仍需检查 `failed/skipped`，运行单检查 `write_failed`。统计和 ID 必须取自真实回执。失败读 `error.type/code/hint/detail/retryable`，按对应指南恢复。

| 退出码 | 含义 |
| --- | --- |
| 0 | 成功 |
| 1 / 2 | API或业务错误 / 校验错误 |
| 3 / 4 | 认证或权限错误 / 网络错误 |
| 5 | 内部错误 |
| 10 | 需要确认 |

内容安全检查只净化输出并提示，不改变退出码。

## 写入确认

先用支持的 `--dry-run` 核对数据和范围。用户已批准且内容一致时用 `--yes`；用户要求先看预览时等批准。退出10时展示 action、关键参数和影响，再按已有批准或新增批准执行。`--yes` 不能绕过后端 errors。

具体命令的预览效果见对应业务指南。通用 `capability run --dry-run` 不调用目标能力，当前也不写 `--output`；更新提示或远端 schema 获取仍可能联网。

## 恢复

- 使用对应流程的稳定键。同批预览、提交、恢复保持键和内容不变，修改内容另建新批次。普通 import 同键换 payload 仍重放原回执，不检查内容变化。
- 超时或回执不明，先核对原任务和提交结果，不换键重传。明确失败的子集保存原回执后，另建稳定键、重新预览；成功项不重传。
- 输出文件失败先读 `error.detail` 的 `committed`、真实结果和原键。`committed: true` 表示已提交，仍需读逐行失败；不能因本地保存失败重做写入。
- 查询、解析、写入、地图各阶段分别报告。授权失败读[授权指南](auth.md)，不对所有错误重新登录。
